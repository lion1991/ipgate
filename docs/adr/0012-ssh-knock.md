# ADR 0012：SSH「仅名单可连」加内核敲门

状态：已定案（agent 侧实施中，客户端待做；进度见 `docs/plans/ssh-knock.md`）
日期：2026-11-06
关联：ADR 0007（SSH 是唯一入口、管理通道走 SSH 隧道）、0002（ruleset 布局）、0008（门被拒时的降级）

## 背景

ADR 0007 之后管理通道没有独立端口：客户端经 SSH 隧道进 loopback 上的 Noise。「SSH 仅放行名单可连」开关因此同时收紧了管理通道——设备出口 IP 不在名单里就连不上，也就没法「放行本机」。电脑和手机不在同一网络时，电脑开了开关，手机（出口 IP 常变）基本不可用。

仅密钥登录挡不住 sshd 认证前的漏洞（2024 年 regreSSHion、xz 后门都在认证之前），用户要求保留「SSH 对扫描不可见」。

## 决策

| # | 决策 | 理由 |
|---|------|------|
| 1 | 「仅名单可连」开着时，SSH 放行 = 名单内源 IP **或** 刚敲过门的源 IP | 已配对设备在任何网络都能自己开门，扫描器仍看不到 sshd |
| 2 | 敲门完全在内核里做：`udp dport <K>` 且载荷前 16 字节等于口令 → 源 IP 写进 `knock4/knock6`（`update`，60 秒超时），包丢弃不回应 | 不需要监听进程，agent 挂了照样能开门；对扫描器无回应，与 default-drop 下的其他端口不可区分 |
| 3 | 口令与端口由 access key 派生：`SHA-256("ipgate-knock-v1" ‖ access_key)`，前 16 字节为口令，第 17–18 字节（大端）模 40000 加 20000 为 UDP 端口 | 已配对设备都持有 access key，无需重新配对、不改二维码、不新增配置项；每台主机端口不同，不留统一特征。重置 access key 时口令随之更换 |
| 4 | 敲门不是鉴权，口令静态即可 | 门开了还要过 SSH 密钥和 Noise。抓包重放只能让对方看到 sshd，不能登录；被吊销的设备同理 |
| 5 | 只有口令匹配的包被丢弃；端口撞上真实 UDP 服务时其余包照常走后续规则 | 派生端口可能与公开 UDP 端口重合，不能因此误伤 |
| 6 | 已建立的连接靠 `ct state established` 保持，门过期不断线 | 客户端只需每次新建 SSH 连接前敲一次 |
| 7 | 内核 / nft 不认敲门规则时，按 ADR 0008 决策 7 逐级退回：先去掉敲门保留转发门，再反过来，最后两者都去掉。开启「仅名单」时敲门被拒 → 恢复原 ruleset、报错、不改设置；启动或重建时被拒 → 保留「仅名单」（尊重收紧意图），上报敲门未生效 | 开关打开却没有敲门，就回到手机进不来的老问题，所以打开时宁可失败；已经开着的不能因内核变化被悄悄放开 |
| 8 | 客户端每次建 SSH 连接前都敲门（IPv4 / IPv6 各发一包），不管主机是否开了「仅名单」 | 刚换网络时客户端拿不到主机设置；一个 UDP 包的代价可忽略 |
| 9 | `AgentSettings` 上报 `ssh_knock_port` 与 `ssh_knock_active`，客户端在「安全」里显示敲门端口 | 云安全组须放行该 UDP 端口，否则敲门包到不了虚拟机 |

## 已否决

- **删掉开关，SSH 永远对全网开放**：最简单，但挡不住 sshd 认证前漏洞（用户否决）。
- **保留开关只加强警告**（开启前列出其他设备）：矛盾不变，手机照样进不来。
- **自动放行设备上次连接的 IP**：IP 变了之后新 IP 本来就连不上，不解决问题。
- **agent 用户态监听 UDP 做 SPA**：要多一个监听进程和协议，agent 挂了就开不了门；内核规则做得到同样的事。
- **出站汇合**（客户端把 IP 交给中转服务，agent 轮询拉取）：能绕过封 UDP 的网络，但要一个常驻的中转服务，它挂了全部主机都进不去，单点代价大于收益。
- **按时间滚动口令**：内核算不了 HMAC，滚动要靠 agent 改写规则，又把 agent 拉回依赖链；口令只管「看不看得见」，静态足够。

## 已知限制

- 封 UDP 的网络、云安全组未放行敲门端口：敲不开，退路是名单内 IP 直连。
- UDP 与 TCP 走了不同出口（代理只接管 TCP、多出口 CGNAT）：敲开的不是 SSH 的来源 IP。
- 整表重建（改开关、改公开端口）会清空 `knock4/knock6`：已建立的连接不受影响，正在敲门的客户端重敲即可。
- 派生端口落在本机 UDP 端口转发（native / dnat 工具 / Docker `-p`）的监听区间内时，敲门包在 prerouting 就被 DNAT 走、到不了 input 链，敲门静默失效，`ssh_knock_active` 仍报 true。
- 整表 apply 因与敲门无关的临时故障失败时，也会被记成敲门被拒并降级，直到下次整表重建（重启或改设置）才恢复；`ssh_knock_active=false` 如实上报。
- 救援 / 审计命令（`ssh-expose --open`、`forward-expose`、`status`、`print-ruleset`）只读 access.key，读不到就不带敲门继续，不会被损坏的密钥卡住。

## 验证

- 2026-11-06 在真机（Debian 12，内核 6.1，nft 1.0.6）用独立测试表实测：敲门前丢弃、错误口令不入集合、正确口令入集合且带超时、敲门后能连、过期后已建立连接不断、过期后新建连接被丢；`update` 重复敲门会把倒计时刷回 60 秒。
- agent 实际渲染的完整 ruleset（敲门 + 转发门 + IPv6 规则）在同一台机器上 `nft -c` 校验通过。
- 未验证：el7（nft 0.8）、IPv6、手机网络；靠决策 7 降级兜底。
