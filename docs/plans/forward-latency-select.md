# 端口转发多目标按延迟选择实施方案（ADR 0014）

定案见 `docs/adr/0014-forward-latency-select.md`。每步单独提交、可单独回滚。

## 步骤

1. **proto + agent**（agent 0.2.13，先以预发布发出）：✅ 2026-11-16 代码与容器实测完成（见 ADR 0014「验证」），未发版。
   - proto：`ForwardRule` / `AddForwardRequest` 增额外目标列表与可选 TCP 探测端口（`serde(default)`，旧 state 原样读）；校验每个目标的端口段、纯 UDP 规则必须有探测端口；`ForwardView` 增各目标状态与上次切换信息。
   - agent：独立探测线程（5 秒一轮，各目标并发 connect）维护内存里的健康与延迟窗口；选择逻辑按 ADR 0014 决策 5–7 写成纯函数；选中目标变化时触发 `apply_now`，与 API、`resolve_loop` 的落地串行；`resolve_one` 对选中目标解析与做禁区检查。
   - 判挂切走时经 ctnetlink dump 并按回程源过滤后逐条删除 conntrack 记录（决策 9），失败只告警。
   - CLI：`forward-add` 可重复给 `--alt host[:port]` 与 `--probe-port`；`forwards` 列出各目标、在用目标与上次切换（实时延迟只在服务内存里，CLI 看不到）。
   - 私有 client 仓库同步补上新字段的空值，保证 core/ffi 能编译（多目标还没接）。
2. **客户端 core + ffi**：暴露多目标、探测端口与目标状态字段；旧 agent 提示升级（≥ 0.2.13）。✅ 2026-11-16
   - 客户端拿不到 agent 版本，旧 agent 又会静默丢掉不认识的字段，所以不在提交前判断：发了额外目标、返回的规则里没有，就报「agent 过旧，只按第一个目标保存了」。
   - 表单的额外目标空行忽略，端口空即沿用主目标端口；提交前在 core 里先跑一遍 proto 的 `validate_targets`，与 agent 同一套校验。
   - Mac 编辑表单暂时原样带回已有的额外目标和探测端口，避免在多目标编辑界面做好之前，一保存就把它们清掉。
3. **Mac 客户端**（AppKit，ADR 0010）：编辑页增删目标、纯 UDP 时必填探测端口；列表与详情显示各目标延迟、存活、当前在用、上次切换时间与原因。 ✅ 2026-11-16 代码完成，未装机
   - 编辑表单仍是 SwiftUI：按 ADR 0010 决策 3 评估过，sheet 表单没有分栏动画那类问题，只为加一个区重写成 AppKit 不划算。
   - 编辑表单新增「其他目标」区：每行主机 + 端口，端口留空即沿用上面的目标端口；有其他目标时显示探测端口，纯 UDP 规则必填；最多 8 个目标。叫「其他目标」不叫「备用目标」，因为各目标不分主次（决策 1）。
   - 列表：映射显示当前在用的目标；多目标规则每个目标占一行，显示延迟 / 判挂 / 未探测，在用的打勾，悬停看解析出的 IP；第二行附上次切换的时间与原因。多目标规则不再显示「解析为 X」（那是在用目标的 IP，不一定是第一个目标的）。
   - 保存失败也刷新列表（旧 agent 会先按单目标保存，再由 core 报错）。
   - 有多目标规则时，转发页可见期间每 10 秒静默重拉列表（只拉转发列表，复用常驻会话；窗口全被挡住、正在刷新或增删改时跳过；失败不提示）。2026-11-16 试用中发现：保存后马上刷新拿到的全是「未探测」，之后不刷新就一直停在那。用户确认要这个开销。
4. **发布**：自己的主机先装预发布试用，没问题再转正式版。
   - 2026-11-17 v0.2.13 作为预发布发出：发布前两轮 opus 独立审查，修掉「按延迟切走后旧目标再挂，UDP 流卡在死目标上」等问题（见 ADR 0014 验证）；main 推送后 CI 绿，再打 tag。还没装到自用主机。
   - x86_64 musl 的构建与测试交给远程 CI：推送 main 后 `build-agent` 自动跑测试并构建，绿了再打 tag。不在 Mac 上模拟 amd64 交叉编译（用户定：太吃本机性能）。本地容器 e2e 只在 arm64 上跑。

## 验证

- 单元：选择函数（判挂立即切、全挂停在原目标、延迟差不够 20% / 10ms 不切、不够 60 秒不切、恢复计数）；校验（纯 UDP 缺探测端口、目标端口段形状）；ctnetlink 报文编解码。
- e2e（netns）：两个后端，杀主后端约 15 秒后新连接走另一个；给一个后端加 `tc netem` 延迟，60 秒后切到快的；UDP 持续发包时杀当前目标，确认 conntrack 被删、流量改走存活目标。
- 回归：单目标规则渲染的 nat 表与 0.2.12 逐字节一致。
